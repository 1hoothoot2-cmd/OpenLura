# Sprint P3.1 – SkyGuide Foundation

## Scope

P3.1 introduces SkyGuide as a focused Aviation Intelligence Assistant inside
the existing Live Map. Desktop keeps Aircraft Details at the lower left and
SkyGuide at the lower right. Mobile uses one bottom sheet with Details and
SkyGuide tabs, so the map remains the product context.

## Architecture

The SkyGuide domain owns aviation scope classification, query normalization,
Smart Action definitions, capability availability and honest foundation
responses. The React presentation layer owns only interaction and visual
state. Live Map supplies selected-aircraft, viewport, lifecycle and available
Flight History context without requiring the user to repeat it.

Future live data, weather, news, controlled search, memory and notification
integrations are represented as explicit capabilities. P3.1 does not implement
adapters or pretend those capabilities are available.

## Scope enforcement

The local deterministic scope policy accepts questions containing explicit
aviation concepts. Empty and unrelated questions receive a calm refusal. This
is a presentation guard for the foundation, not a replacement for server-side
model guardrails in a future AI-provider sprint.

## Data and privacy

P3.1 performs no AI, backend, provider, location, memory, Supabase or web-search
request. Questions remain in component memory and disappear on navigation or
refresh.

## Known limitations

- Answers are honest foundation messages, not generated intelligence.
- Smart Actions prepare a question but do not call unavailable services.
- Discover content is editorial placeholder content.
- There is no public standalone SkyGuide page.
- The vocabulary policy intentionally stays conservative until a server-side
  aviation-intelligence provider and its own scope enforcement are introduced.
