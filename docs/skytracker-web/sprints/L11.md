# Sprint L11 — Historical Track

## Scope

L11 adds one selection-bound historical track to the existing live map. It
does not change aircraft polling, motion, replay, search, filters, favorites,
airports, accounts, AI, or the SkyTracker backend.

## Data flow

```text
Selected provider-neutral aircraft
→ same-origin SkyTracker web adapter
→ GET /v1/flightlegs/{aircraftId}
→ internal flightId
→ GET /v1/historical-tracks/{flightId}
→ validated provider-neutral track
→ segmented GeoJSON
→ one MapLibre source and one line layer
```

The narrow same-origin adapter is required because the existing FlightLeg and
Historical Track backend handlers do not expose browser CORS headers. It only
forwards existing contracts and adds no provider or business logic.

## Rendering

- Source: `skytracker-historical-track`
- Layer: `skytracker-historical-track-line`
- Layer type: `line`
- Style: cyan, 58% opacity, rounded joins and ends, zoom-aware 1.2–2.1 px width
- Order: above the basemap and directly below all aircraft layers
- Segments: every backend segment becomes its own `LineString`; gaps are never
  connected.

Only the selected aircraft can own a track. A selection change aborts the old
request and replaces the source data. Deselecting writes an empty feature
collection. There is no polling, interval, refresh, browser persistence, or
extra cache.

## UI states

The existing aircraft detail panel contains an `aria-live="polite"` status:

- `Loading historical track…`
- `{completeness} · {point count} points · {segment count} segments`
- `No historical track available.`

Errors remain compact and do not obscure the map.

## Known development-data limitation

The current development backend track contains three points across roughly
0.04 degrees longitude. At the initial Western Europe zoom this route is only
a few pixels long. The source, layer, success status, point count, and segment
count are proven, but this deliberately small backend fixture is not a strong
visual route demo at the initial zoom.
