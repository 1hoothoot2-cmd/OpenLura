# Sprint B4 - OpenLura Production Connection

## Scope

Connect the existing SkyTracker web experience to the accepted production
backend through a same-origin Next.js route. No provider, backend, motion or
domain contract changes are part of this sprint.

## Production chain

```text
OpenLura browser
-> /api/skytracker/aircraft
-> Vercel route handler
-> Cloud Run SkyTracker API
-> OpenSky (backend only)
```

The Cloud Run origin is stored only in `SKYTRACKER_API_BASE_URL`. Browser code
contains no Cloud Run URL and requires no Cloud Run CORS permission.

## Budget policy

The web scheduler polls at most once every six minutes. Map movement, tab
visibility and scheduler resets cannot bypass the remaining interval. This is
at most 240 scheduled polls per continuously open browser per day. The backend
Budget Gate remains the global hard stop at 300 provider operations per day,
and backend cache outcomes are forwarded in `X-Cache-Status`.

## Failure policy

- Invalid viewport: same-origin HTTP 400 Problem Details.
- Missing server configuration: HTTP 503 Problem Details.
- Upstream timeout: HTTP 504 Problem Details.
- Unreachable backend: HTTP 502 Problem Details.
- Backend/provider responses: status and safe response headers are preserved.
- The last accepted aircraft snapshot remains visible during reconnecting.

## Acceptance

Production acceptance requires:

1. the Vercel production variable to be configured;
2. a successful production deployment;
3. aircraft visible at `https://openlura.ai/skytracker/live`;
4. browser traffic only to the same-origin API route;
5. no CORS, console, hydration or duplicate-request errors;
6. request correlation visible in Vercel and Cloud Run logs.
