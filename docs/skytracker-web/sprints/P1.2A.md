# Sprint P1.2A – Smooth Global Loading & Worldwide Aircraft Search

## Root cause

P1.2 queued every missing region thirty seconds after the previous request.
Twelve planned regions therefore required roughly five and a half minutes
before the last request could start. The motion freshness ceiling was four
minutes, while a loaded focus tile refreshed only after the full tile rotation.
Search derived results exclusively from the merged viewport snapshot.

## Adaptive loading

- The tile containing the viewport centre is the focus tile.
- The focus tile starts immediately.
- Other visible tiles follow centre-first.
- A one-tile background ring fills unused capacity up to twelve planned tiles.
- Request starts use a two-second cadence and remain strictly sequential.
- A new viewport replaces the pending queue; an obsolete in-flight request is
  aborted by the map runtime.
- Fresh cached tiles are reused.
- After initial coverage the focus tile is the six-minute refresh target.
- The session ceiling remains 240 request starts per rolling day.
- The backend Firestore Budget Gate remains authoritative.

Aircraft already on screen remain while the new plan loads. The motion engine
keeps its existing progressive slowdown, but its hard ceiling is seven minutes
so a valid moving target does not freeze before the six-minute focus refresh.
No motion frame performs network work.

## Worldwide search

Typing remains completely local and causes no request. A worldwide search is an
explicit action for a 2–16 character callsign or aircraft ID:

```text
Browser
→ /api/skytracker/aircraft/search
→ Cloud Run /v1/aircraft/search
→ OpenSky states
```

The browser never receives or calls the Cloud Run URL. The backend:

- uses an exact `icao24` provider filter for a six-character hexadecimal ID;
- otherwise searches one current global state snapshot for callsign or ID;
- coalesces equal global operations;
- caches the provider snapshot for sixty seconds;
- returns at most eight provider-neutral aircraft;
- permits at most twenty global search provider operations per day;
- conservatively books four aircraft-provider budget units per cache miss.

Selecting a worldwide result injects only that current provider-neutral
aircraft into presentation state, moves the map to its coordinates, gives the
new region focus priority, selects it, updates URL state and opens the existing
details. Follow remains off.

## Production gate

The frontend route depends on the new backend route. Production activation
therefore requires an immutable backend image and a Cloud Run revision update.
That cloud mutation is intentionally outside autonomous local validation and
requires the Product Owner cloud gate before the frontend is deployed.
